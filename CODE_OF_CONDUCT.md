# Code of Conduct

## Purpose

The Amazon BR-163 PyEO project is committed to maintaining a respectful, inclusive, and constructive environment for everyone who participates in the project.

This Code of Conduct applies to repository discussions, issues, pull requests, reviews, documentation, and other project-related communication.

## Expected Behaviour

Project participants are expected to:

- Communicate respectfully and professionally.
- Provide constructive, technically relevant feedback.
- Respect differing experiences, perspectives, and levels of expertise.
- Focus criticism on the work rather than the individual.
- Accept reasonable correction and respond constructively.
- Protect confidential information, credentials, and restricted data.
- Follow the repository's documented contribution and quality-assurance requirements.

## Unacceptable Behaviour

The following behaviour is not acceptable:

- Harassment, intimidation, discrimination, or personal attacks.
- Insulting, demeaning, threatening, or deliberately disruptive language.
- Repeatedly dismissing reasonable technical feedback without discussion.
- Publishing another person's private information without permission.
- Sharing credentials, access tokens, or restricted project information.
- Deliberately introducing malicious, misleading, or destructive changes.
- Misrepresenting unvalidated work as completed or operational.
- Disrupting project discussions or reviews in bad faith.

## Technical Collaboration

Contributors should keep technical discussions focused on evidence, reproducibility, and project requirements.

Disagreement is acceptable when handled constructively. Participants should explain the reasoning behind recommendations, identify supporting evidence where available, and acknowledge uncertainty when conclusions have not been fully validated.

## Reporting

Concerns should be reported privately to the repository maintainer rather than escalated through public arguments.

A report should include, where possible:

- A description of the incident.
- Relevant dates and communication records.
- Repository links, issue numbers, or pull-request references.
- Any additional context needed to assess the concern.

Do not include sensitive personal information unless it is necessary for reviewing the report.

## Enforcement

The repository maintainer is responsible for reviewing reported incidents and determining an appropriate response.

Possible actions include:

1. Private clarification or correction.
2. A formal warning.
3. Removal of inappropriate content.
4. Temporary restriction from project participation.
5. Permanent removal from project participation.

Enforcement decisions should be proportionate to the behaviour, its impact, and whether it is repeated.

## Scope

This Code of Conduct applies within project spaces and when an individual is representing the project in public communication.
